Mavell CN10K RAS implementation
===============================

Marvell CN10K implements the ARMv8 RAS (Reliability, Availability & Serviceability) specification.

This decouples the tracking of hardware exception events from any outage
to the data being transferred, allowing a RAS-aware OS to handle the outage
as it sees fit by analyzing the context in which the data is being used.

Errors in memory, cache, and AP cores are detected by the hardware and handled by ATF
in firmware first mode. Kernel notified via Software Delegated Exception Interface (SDEI).
RAS error records are exchanged between ATF and kernel via a shared memory buffer.
The shared memory layout is described under the Device Tree "sdei-ghes" node.
For layout details of the Device Tree "sdei-ghes" node see the following kernel document:
Documentation/devicetree/bindings/edac/marvell-sdei-ghes.txt

Uboot-based systems utilize Device Tree for communication and set up EDAC framework
driver octeontx_edac for RAS error reporting. On the other hand, ACPI-based systems
do not have access to the Device Tree, and the ACPI table HEST keeps in sync with
the Device Tree by EDK2 firmware and ACPI driver.
For that systems, HEST fully describes shared buffer location, error status block,
and notification type. RAS support for ACPI systems is entirely based
on Kernel mainline APEI, GHES framework. Mentioned shard memory is managed in
a circular buffer manner. RAS error records from the buffer support CPER, GHES
framework layout structure that is maintained by APEI.
The same structure is supported by the EDAC driver for the system that does not support ACPI
but supports EDAC. From a firmware perspective, both RAS reporting schemas look identical.
EDAC driver fulfills the requirement of the framework in the error report, injection,
and corresponding controls and statistics data. For more details, refer to
Documentation/devicetree/bindings/edac/marvell-sdei-ghes.txt and corresponding Documentation/edac.txt
Kernel ACPI-based system works under APEI framework for error report and
uses external module for error injection in future error injection (EINJ) ACPI table
should handle error injection.

RAS error types
---------------
These can be Correctable (CE), Uncorrectable Unrecoverable (UEU) and
Uncorrectable Recoverable (UER) errors.
  CE error is a single-bit ECC error in memory or cache.
  UEU error is a double-bit ECC error in the secure memory region.
  UER error is a double-bit ECC error in a non-secure memory region.

Note: Only DSS uncorrected errors(UE) are categorized by firmware
as UEU and UER based on the security attribute of the error address.
Firmware support compiles time control SKIP_REBOOT_ON_RAS_FATAL for UEU error types behavior.
Uncorrected errors from all other modules are treated as fatal in the current firmware implementation.

The firmware enables exceptions in relevant CN10K hardware units
CORE (ARM processor), DSS (DRAM subsystem, DRAM Controller),
TAD (LLC, Cache Tag And Data), MDC (Memory Diagnostic Controller)
and performs the following actions:
- Capture hardware description of the error
- Convert the hardware description of the error to CPER (Common Platform Error Record) and GHES format
- Collect error records per hardware component ring buffer.
- Make SDEI notification to Kerne driver
- Kernel handles RAS records based on system type ACPI or DT.


Configurations to enable RAS Error Reporting for Device Tree base systems
=========================================================================
Enable module config:
RAS=y
EDAC=y
ARM_SDE_INTERFACE=y
EDAC_OCTEONTX=y

Configurations to enable RAS Error Reporting for ACPI base systems
==================================================================
Enable module config:
CONFIG_ACPI=y
CONFIG_ACPI_APEI=y
CONFIG_ACPI_APEI_GHES=y
MARVELL_CN10K_EINJ=y



RAS EDAC Error injection DSS
============================

EDAC based interface for error injection from sysfs
/sys/devices/system/edac/mc/mc0

EDAC SMC based interface for error injection exemple:
	ls -l /sys/devices/system/edac/mc/mc0
	address              - Physical Address to corrupt
	ce_count             - CE error counter
	ce_noinfo_count      - enadle/disable logging for CE
	error_type           - type of error SEC/DED and position of bit to corrupt
	                            29   - Set bit 29 for DSS error injection
	                            0..7 - bit position to corrupt
	                            8    - error type 0 = DED (double), 1 = SEC (single)
	inject               - Trigger error injection
	max_location
	mc_name              - Memory controller name "dss"
	power
	reset_counters       - Reset CE/UE counter to 0
	seconds_since_reset
	size_mb              - Unused property currently
	ue_count             - UE counter
	ue_noinfo_count      - enadle/disable logging for UE
	uevent

Example: Flip one bit at address 0x2fffff000
--------------------------------------------
echo 0x2ffff0000 > address
echo 0x20000101 > error_type
echo 1 > inject

Output example:

EDAC MC0: 1 CE on (single-bit ECC status:0x103 addr: 0x2ffff0000 rank:0 bank:3 row:49151 col:0 bit_pos:3  page:0x2ffff offset:0x0 grain:1 syndrome:0x0 - DMC1,Rank0,BG2)

		1 CE         - one correctable error
		DMC1         - DMC 1 or memory controller channel 1
		rank:0       - Rank 0
		BG2          - Bank Group 2
		bank:3       - Bank Address 3
		row:49151    - DRAM row 49151
		col:0        - DRAM collumn 0
		bit_pos:3    - DRAM bit positionin row
		page:0x2ffff - Physical page
		offset:0x0   - page + offset make physicall address 0x2ffff0000, in current test system page offset 16 bits long.
		status:0x103 - Raw value from register ddrc_ch0_eccstat

Flip two bits at address 0x2ffff0000
------------------------------------
Multi-bit errors require DRAM reinitialization to fix errors which is true for cold system reset.
setenv bootargs 'reboot_mode=cold'
echo 1 > /sys/module/edac_core/parameters/edac_mc_panic_on_ue
echo 0x2fffff000 > address
echo 0x20000001 > error_type
echo 1 > inject
module/kernel parameter: edac_mc_panic_on_ue=1

Output example:
EDAC MC0: 1 UE R,DMC1,R0,BG2 on  (multi-bit ECC status:0x10003 addr: 0x2ffff0000 rank:0 bank:3 row:49151 col:0 bit_pos:0  page:0x2ffff offset:0x0 grain:1)
		UE R,DMC1,R0,BG2 - UER Recoverable error on DMC1, Rank 0, Bank Grour 2
		UE U,DMC1,R0,BG2 - UEU Unrecoverable error on DMC1, Rank 0, Bank Grour 2

	cd /sys/devices/system/edac/mc/mc0

	echo 0x2ffff0000 > address && echo 0x20000101 > error_type && echo 1 > inject
	echo 0x2ffff0000 > address && echo 0x20000001 > error_type && echo 1 > inject

	echo 0x20000 > address && echo 0x20000101 > error_type && echo 1 > inject
	echo 0x20000 > address && echo 0x20000001 > error_type && echo 1 > inject

	echo 0x3fc008000 > address && echo 0x20000101 > error_type && echo 1 > inject
	echo 0x3fc008000 > address && echo 0x20000001 > error_type && echo 1 > inject

	echo 0xf00000 > address && echo 0x20000101 > error_type && echo 1 > inject
	echo 0xf00000 > address && echo 0x20000001 > error_type && echo 1 > inject

	echo 0x5e1fff000 > address && echo 0x20000101 > error_type && echo 1 > inject
	echo 0x5e1fff000 > address && echo 0x20000001 > error_type && echo 1 > inject

	echo 0x10000000 > address && echo 0x20000101 > error_type && echo 1 > inject
	echo 0x10000000 > address && echo 0x20000001 > error_type && echo 1 > inject

RAS APEI GHES Error injection DSS
=================================

Currently, we do not support EINJ table and use the custom driver for error injection:
MARVELL_CN10K_EINJ=y

0xd         - DSS identifier
0x2ffff0000 - address
0x101       - error type double bit error injection
0x1         - error type single bit error injection

echo "0xd,0x2ffff0000,0x101" > /sys/module/cn10k_einj/parameters/smc
echo "0xd,0x2ffff0000,0x1" > /sys/module/cn10k_einj/parameters/smc

echo "0xd,0x20000,0x101" > /sys/module/cn10k_einj/parameters/smc
echo "0xd,0x20000,0x1" > /sys/module/cn10k_einj/parameters/smc

echo "0xd,0xf00000,0x101" > /sys/module/cn10k_einj/parameters/smc
echo "0xd,0xf00000,0x1" > /sys/module/cn10k_einj/parameters/smc

echo "0xd,0x10000000,0x101" > /sys/module/cn10k_einj/parameters/smc
echo "0xd,0x10000000,0x1" > /sys/module/cn10k_einj/parameters/smc
