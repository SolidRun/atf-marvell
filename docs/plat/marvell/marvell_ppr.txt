Hard Post Package Repair (hPPR) implementation
==============================================

The purpose of this document is to describe the ATF's Hard Post Package Repair (hPPR).

Driver support
1. Hard Post Package Repair When Due (periodic hPPR based on ECS data)
2. Hard Post Package Repair On Demand (manual hPPR based on user-provided data)



Hard Post Package Repair When Due
=================================

J) DDR ECS Statistics Enable (1)
E) DDR Hard Post Package Repair When Due (1)

The PPR driver supports Fail Row address repair for DDR5 based on
collected statistic.
For internal details about DDR5 PPR procedure refer to JESD79-5 4.29.
The Driver (EBF firmware) checks if PPR is needed in the reboot phase if new PPR records
available compared to the last reboot cycle. The records would keep in
PPR region periodically by ATF firmware driver
once in 30 days (PPR cycle) or urgent PPR if ECC Error per Row Counter (EpRC)
for some DRAM row reached MAX_EpRC_THRESHOLD (current value is 128).
The hPPR statistics are collected each MRR cycle periodically (period is 24 hours),
but data update happened as mentioned above urgent PPR or each PPR cycle end.

The decision about the repair is taken based on previously collected statistics.
The statistics are collected in non-volatile memory (spi flash) every 24 hours (MRR cycle)
for all modules, ranks, banks.
After 30 days the driver searches for the most frequently occurred Row for
each DRAM device. If DRAM device has available resources for PPR, driver
decides to perform Fail Row repairing.

The core of the PPR is Error Check and Scrub (ECS inernal DRAM) DDR5 mode with an
error counting scheme. EBF firmware enables ECS after training is done and
DRAM devs in sync with ECC DRAM dev.
ECS is running at the background manual mode. The memory controller uCODE triggers ECS
execution periodically.

The ECS process collects statistics of a failing Row/BGx/BAx, Bank Address (BA)
and saves it at the Mode Registers Read (MRR) MR16-MR20 registers. Full error
scrub of the DRAM is performed every 24 hours.
For more details refer to JESD79-5 4.36.

ATF executes timer callback (24h) and collects statistics from ECS transparency
MR16-MR20 registers for all available Devices/BG/BA/Rows.
ATF saves MRR registers data as a `struct mrr` and EpRC:

struct record_t {
	uint32_t channel   : 5;  // Up to 31 channels
	uint32_t rank      : 1;  // Ranks 0/1
	uint32_t device    : 3;  // Up to 5 Devices currently
	uint32_t bank_gr   : 3;  // Up to 7 Bank Groups
	uint32_t bank_addr : 2;
	uint32_t row_num   : 18;
} __attribute__((packed));

and writes at non-volatile memory into dedicated MRR region.
After 30 days (or after urgent PPR) ATF scans the MRR region and count `struct mrr` and accumulate EpRC for
each rows that were selected by ECS. That records and counters values should be written into
the non-volatile memory PPR region. PPR region records layout is `struct ppr`:

struct ppr {
	uint8_t cases;
	uint8_t EpRCacc;
	uint16_t cycle;
	union {
		uint32_t record;
		union record_t mrr;
	};
} __attribute__((packed));

PPR keep row record
record    - failed raw layout coming from MR16-MR20 registers
cases     - number of occurrences of Failed Row (BG,BA) in last PPR cycle (30 days/Urgent PPR)
EpRCacc   - total number of errors MR19 (accumulated in prr cycle)
            JEST79-5 (4.36.3 ECS Error Tracking) saturated to 0xFF
cycle     - index of first MMR cycle whan row mentioned by ECS (default days counter)

Records should be kept at a head (index head_ppr) of the PPR region.

Later, when there's a reboot, EBF detects that ppr region has valid
data for hPPR, then EBF scans the PPR region to fetch addresses of
failed rows, then it performs hard PPR on those failed rows with
EpRCacc greater than EpRC_THRESHOLD (2).
For multiple failed row in same BA select one with maximum EpRCacc.

Urgent PPR supported in case of EpRC exceeded error threshold value.
EBF can provide PPR procedure after threshold reached and not wait for 30 days.
Header update mrr_max_EpRC after each ECS cycle completed.
If mrr_max_EpRC reached threshold MAX_EpRC_THRESHOLD (128) value.
The origin of mrr_max_EpRC is Max Row Error Count REC[5:0]
Contains number of errors within the row with the most errors.
The make_statistics function prepare PPR region accordingly for EBF PPR procedure.
EpRC is not absolute errors number value. Each bit of EpRC correspond to
configurable range [0-256] by default refer to JESD79-5.

SIGNATURE - does the PPR flash region valid, if it does not match we
erase the PPR flash region as invalid and init from the beginning.

Header contains mrr/ppr index (starting from '0') of the last free record at
corresponding region.

Header saves a number of mrr/ppr cycles. The ppr cycle is share with EBF 'PPR CYCLE'.
'PPR CYCLE' increment every 30 days or on demand.
'MRR CYCLE' increment in daily basis.

Max EpRC keep counter for row with maximum errors in last MRR cycle

Next ppr index point on PPR region record index for next hPPR repair procedure to start from.

The further header can be extended to add communication with EBF and track PPR progress.

Hard Post Package Repair On Demand
==================================

The user is able to point out on particular row to repair it.

Disable concurrent Hard Post Package Repair When Due option required:
	E) DDR Hard Post Package Repair When Due (0)
	I) DDR HPPR Skip Repairing Step (0)
	

Select particular row for repair:
	D) EBF_CONFIG_DDR5_PPR_CHANNEL  (0x0)  (0x0)  (0x0)
	E) EBF_CONFIG_DDR5_PPR_RANK  (0x0)  (0x0)  (0x0)
	F) EBF_CONFIG_DDR5_PPR_DEVICE  (0x0)  (0x0)  (0x0)
	G) EBF_CONFIG_DDR5_PPR_BG  (0x0)  (0x0)  (0x0)
	H) EBF_CONFIG_DDR5_PPR_BA  (0x0)  (0x0)  (0x0)
	I) EBF_CONFIG_DDR5_PPR_ROW  (0x40000)  (0x40000)  (0x40000)

                     to disable hPPR on demand for particular DSS that set row into 0x40000.

Typical use cases
=================

J) DDR ECS Statistics Enable (1)
--------------------------------
	By default we keep statistics collection by ATF even if PPR disabled

E) DDR Hard Post Package Repair When Due (0)
--------------------------------------------
	This option allow "hPPR when due" if set to "1"
	"hPPR when due" disabled by default and EBF driver in reboot cycle skip hPPR

I) DDR HPPR Skip Repairing Step (1)
-----------------------------------
	Disable rows repairing by default, additional option provided to protect rows from repair.
	This safety option allow enable hPPR to check hPPR algorithm, but do not do actual rows repair.
	If this option is "1" both "manual hPPR" and "hPPR when due" will proceed PPR algorithm but skip repairing step.
	To enable repairing use "0":

The valid options are:
E) DDR Hard Post Package Repair When Due (0)
I) DDR HPPR Skip Repairing Step (1)
	Disable all

E) DDR Hard Post Package Repair When Due (1)
I) DDR HPPR Skip Repairing Step (1)
	Debug what hPPR will do but do not utilize resources.

E) DDR Hard Post Package Repair When Due (1)
I) DDR HPPR Skip Repairing Step (0)
	Allow automatic hPPR for all available statistics collected
	MRRid   0       PPRid   15   <--- Lastly added record id is 14 (15 first available)
	MRRc    0       PPRc    5
	maxEpRC 0       hPPRnxt 10   <--- At boot start to check records from index 10 (hPPRnxt)
	hPPR has next records to check: 10,11,12,13,14 - totaly 5 recodrs between head and tail [hPPRnxt - PPRid)
	In case of PPRid == hPPRnxt nothing for hPPR consideration




 ECC Error Check and Scrub Statistics
=====================================

For ECC Error Check and Scrub Statistics collection refer to JESD79-5A (4.37 DDR5 ECC Transparency and Error Scrub)

ATF hPPR driver allow ECS statistics collection by EBF menu option:
J) DDR ECS Statistics Enable (1) - enable
J) DDR ECS Statistics Enable (0) - disable

The driver checks MR16-MR19 once in 24 hours and preserves data only if ECS has reported an error
for a row in DRAM. It is nothing to preserve if ECS did not find an error.
Flash storage for statistics keeps the header at from of the data.

VERBOSE: hPPR SIG       cafebaba
MRRid   26      PPRid   18
MRRc    16      PPRc    196
maxEpRC 8       hPPRnxt 0

hPPR SIG - it is flash ECS region signature
For debugging reason driver allows flash storage to erase if signature mismatch.

MRRid    - index of last record in MRR region
Driver use MRR region for statisctics collection

PPRid    - index of last record in PPR region
Driver use PPR region to instruct which resource should be repared

MRRc     - MRR cycle index, index to count days
PPRc     - PPR cycle index, index to count days

maxEpRC  - Error rep Row Counter refer to JESD79-5A (4.37 DDR5 ECC Transparency and Error Scrub)
EpRC is data from ECS MR16-MR19 this field track maximum faund EpRC for some row in some device

hPPRnxt  - index of record in PPR region to start hPPR from this index and till index in PPRid

H) DDR ECS EpRC Threshold (128) - This option control statistics summary making.
The driver allows urgent hPPR When Due. If some DRAM device ECS highlight row EpRC reached this threshold
the drive will make statistics summary immediately.
